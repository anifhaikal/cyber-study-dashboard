02 / NETWORK MODELS

How network communication
moves layer by layer.

Reference models
PRACTICAL MODEL

TCP/IP model

The TCP/IP model describes how the internet actually moves data. It has four layers. Data moves down the sender’s stack, crosses the network, then moves up the receiver’s stack.

4 · ApplicationPurpose: provides network services directly to software such as browsers, email clients, and remote administration tools. What happens: DNS resolves names, HTTPS carries web requests, and SSH carries secure shell commands. Data is represented as application messages. Security focus: validate protocols, certificates, authentication, and application-layer input because attacks can exploit services such as insecure HTTP or DNS.
3 · TransportPurpose: creates communication between applications on two devices and separates services with port numbers. What happens: TCP performs a three-way handshake, numbers data, retransmits missing segments, and controls flow; UDP sends datagrams without establishing a connection. Data is represented as segments for TCP or datagrams for UDP. Security focus: inspect ports, unexpected listeners, connection floods, and abuse such as SYN floods.
2 · InternetPurpose: provides logical addressing and moves packets between networks. What happens: IP adds source and destination addresses and routers choose the next hop; ICMP reports delivery errors and supports diagnostics such as ping. Data is represented as IP packets or datagrams. Security focus: investigate spoofed addresses, unexpected routes, ICMP floods, and suspicious traffic crossing network boundaries.
1 · Network AccessPurpose: delivers data across the local link and converts packets into frames and physical signals. What happens: Ethernet or Wi-Fi adds local MAC addresses, ARP maps an IP address to a local MAC address, and a cable, fiber, or radio transmits bits. Data is represented as frames and bits. Security focus: protect wireless access, monitor ARP manipulation, secure switches, and restrict unauthorized devices.

Scenario: opening an HTTPS website

  1. Application: DNS resolves the domain; HTTPS creates the web request.
  2. Transport: TCP uses a three-way handshake and port 443 carries the HTTPS stream.
  3. Internet: IP addresses route packets between your device, router, and web server.
  4. Network Access: Wi-Fi or Ethernet frames carry each packet to the next device; ARP finds the local gateway’s MAC address.
REFERENCE MODEL

OSI model

The OSI model is a seven-layer framework for learning, designing, and troubleshooting networks. It separates responsibilities so an analyst can identify where a failure occurs.

7 · ApplicationPurpose: gives user applications access to network services. What happens: a browser creates an HTTPS request, an email client uses SMTP or IMAP, and a DNS client asks for a name resolution. Data is application data. Security focus: authentication, authorization, secure protocols, input validation, and protection against application-layer attacks.
6 · PresentationPurpose: makes data understandable and safe for the receiving system. What happens: data is translated into a common format, compressed to reduce size, encrypted before transit, and decrypted or decompressed by the recipient. Data may be encoded text, compressed media, or ciphertext. Security focus: TLS encryption, certificate validation, cryptographic algorithms, and preventing weak or incorrectly implemented encryption.
5 · SessionPurpose: manages the start, continuation, and end of a conversation between applications. What happens: a session is established, kept alive, synchronized, and closed after the exchange. Examples include a logged-in web session or an active video meeting. Security focus: session IDs, timeouts, reauthentication, and preventing session hijacking or replay.
4 · TransportPurpose: delivers data between the correct applications and manages end-to-end communication. What happens: TCP establishes a connection and provides ordering, acknowledgments, retransmission, and flow control; UDP provides faster delivery without those guarantees. Port numbers identify services. Data is represented as segments or datagrams. Security focus: port scanning, unauthorized services, denial-of-service floods, and malicious connection behavior.
3 · NetworkPurpose: identifies devices across interconnected networks and chooses paths for traffic. What happens: IP adds logical addresses, routers examine destination addresses, and packets move from network to network through multiple hops. Data is represented as packets. Security focus: routing manipulation, IP spoofing, unauthorized paths, network segmentation, and filtering at firewalls.
2 · Data LinkPurpose: delivers data between devices on the same local network. What happens: packets are placed into Ethernet or Wi-Fi frames, MAC addresses identify local interfaces, and switches or access points forward frames. Error detection can identify damaged frames. Data is represented as frames. Security focus: rogue access points, MAC spoofing, ARP poisoning, VLAN weaknesses, and unauthorized switch access.
1 · PhysicalPurpose: transmits raw binary bits through a physical medium. What happens: network hardware converts bits into electrical pulses on copper, light pulses in fiber, or radio waves over wireless. Connectors, antennas, cables, repeaters, and signal strength affect transmission. Data is represented as bits and signals. Security focus: cable tapping, device tampering, radio interference, physical damage, and unauthorized access to networking equipment.

Scenario: joining a video call

  1. Application: The meeting app requests the call service.
  2. Presentation: Audio/video codecs format data and encryption protects it.
  3. Session: The meeting session authenticates participants and stays active.
  4. Transport: TCP or UDP carries control and media traffic using ports.
  5. Network: IP routes packets to the meeting servers and other participants.
  6. Data Link: Wi-Fi or Ethernet frames use MAC addresses on each local network.
  7. Physical: Radio, copper, or fiber carries the bits as signals.
